## ADDED Requirements

### Requirement: Provider auto-detection for policy injection

The system SHALL detect which entry files exist in the target directory among `CLAUDE.md`, `AGENTS.md`, and `.github/copilot-instructions.md`, and SHALL treat every entry file found as a target for policy injection. The system SHALL NOT require explicit provider configuration.

#### Scenario: Multiple entry files present

- **WHEN** a target directory contains both `CLAUDE.md` and `.github/copilot-instructions.md`
- **THEN** the system SHALL inject the policy block into both files, each formatted per its provider's rules

#### Scenario: No entry file present

- **WHEN** a target directory contains none of `CLAUDE.md`, `AGENTS.md`, or `.github/copilot-instructions.md`
- **THEN** the system SHALL skip policy injection and SHALL print an informational message, and SHALL NOT treat this as an error (exit code remains 0)

### Requirement: Idempotent policy block injection

The system SHALL wrap the injected core policy rules in a `<!-- SAIFG:START v<version> -->` / `<!-- SAIFG:END -->` marker block. When an entry file already contains this marker block, the system SHALL replace only the content between the markers, preserving all other content in the file. When no marker block exists, the system SHALL append a new one to the end of the file.

#### Scenario: Re-running init updates an existing block

- **WHEN** `saifg update --target ./my-project` runs against a `CLAUDE.md` that already contains a `<!-- SAIFG:START v1 --> ... <!-- SAIFG:END -->` block from a prior install
- **THEN** the system SHALL replace only the text between the markers with the current policy content, leaving the rest of `CLAUDE.md` unchanged

#### Scenario: First-time injection appends a new block

- **WHEN** `saifg init --target ./my-project` runs against a `CLAUDE.md` with no existing SAIFG marker block
- **THEN** the system SHALL append a new `<!-- SAIFG:START v<version> -->...<!-- SAIFG:END -->` block to the end of the file without modifying existing content

### Requirement: Provider-specific policy content strategy

The system SHALL install `.saifg/policy.md` into the target project during `saifg init`. For entry files that support file import syntax (`CLAUDE.md`), the injected core policy block SHALL reference `.saifg/policy.md` via `@.saifg/policy.md` import syntax rather than duplicating its full content. For entry files without import support (`AGENTS.md`, `.github/copilot-instructions.md`), the core governance rules SHALL be fully inlined within the injected block, independent of whether `.saifg/policy.md` exists.

#### Scenario: Claude entry file uses import syntax

- **WHEN** the system injects the policy block into `CLAUDE.md`
- **THEN** the injected block SHALL contain an `@.saifg/policy.md` reference and SHALL NOT duplicate the full policy text inline

#### Scenario: Copilot entry file inlines core rules

- **WHEN** the system injects the policy block into `.github/copilot-instructions.md`
- **THEN** the injected block SHALL contain the full core governance rules text inline, without relying on `.saifg/policy.md` being read automatically

### Requirement: Injected policy states assistant-generated content governance

The injected core policy content SHALL state that content generated by the assistant at runtime (without human confirmation) SHALL be classified under the `usr.` scope, SHALL be trackable in the target project's git repository, and SHALL NOT be published if the target project itself publishes an npm package.

#### Scenario: Policy content includes the governance statement

- **WHEN** a user reads the injected `<!-- SAIFG:START -->` block in any entry file
- **THEN** it SHALL include a statement that assistant-generated unconfirmed content uses the `usr.` scope, is git-trackable, and is excluded from npm publication
